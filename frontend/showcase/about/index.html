About the Project

AI-NIDS was engineered as an applied research project investigating the feasibility of real-time machine learning inference directly on network packet flows. Below are our core motivation, design principles, technical challenges, and engineering roadmap.

PROBLEM CONTEXT

The Challenge of Modern Intrusion Detection

Traditional network intrusion detection systems (such as Snort and Suricata) rely predominantly on deterministic signature matching. While highly effective for known exploits, signature engines suffer from three fundamental limitations:

1. Payload Encryption: As internet traffic approaches near-total TLS encryption, deep packet inspection (DPI) cannot read application payloads without intrusive certificate inspection proxies.

2. Novel Zero-Day Variants: Attackers routinely alter shellcode signatures, obfuscate payloads, and modify binary encodings to evade static regular expression rules.

3. High Maintenance Overhead: Maintaining rule lists across thousands of evolving attack vectors requires dedicated threat intelligence engineering.

The AI-NIDS Approach: By analyzing the statistical behavior of conversational flows—such as inter-arrival rates, directional byte asymmetry, packet sizes, and TCP control flag transitions—AI-NIDS classifies malicious activity independently of payload contents, preserving privacy while detecting anomalous network behavior.

PROJECT OBJECTIVES

Design Principles & Engineering Goals

Rather than building a theoretical machine learning simulation on static CSV files, the project pursued five concrete engineering objectives.

OBJECTIVE 01 // COMPLETE OPERATIONAL AUTONOMY

Physical Wire to Browser Screen

Build an end-to-end, runnable system that captures raw Ethernet/IP frames from physical Linux network sockets (wlan0 / eth0), tracks bidirectional flows in memory, extracts mathematical features, performs inference, logs structured alerts, and renders real-time telemetry on an operator console.

OBJECTIVE 02 // EDGE EFFICIENCY WITHOUT GPUS

Commodity CPU Inference

Avoid bloated deep neural network frameworks requiring multi-gigabyte GPU runtimes. Utilize an optimized Random Forest ensemble delivering sub-10ms inference latency entirely on commodity CPU cores, enabling edge deployment on modest hardware appliances.

OBJECTIVE 03 // SCIENTIFIC & TECHNICAL HONESTY

Explicit Limitation Documentation

Transparently separate offline dataset accuracy (99.74%) from live network performance. Document class overlaps and streaming feature gaps rather than inflating detection metrics or presenting marketing exaggerations.

OBJECTIVE 04 // ZERO CLOUD DEPENDENCY

Air-Gapped Privacy & Portability

Eliminate external telemetry tracking, cloud APIs, and complex daemon setups. Package the datastore into an embedded SQLite database and the web client into pure static files runnable on any isolated, air-gapped system.

ARCHITECTURAL CHOICES

Core Engineering Decisions

The pivotal technical choices that shaped the design and operational behavior of the AI-NIDS architecture.

DECISION 01

Hybrid Detection Architecture

Early prototypes relied exclusively on machine learning classification. However, evaluating reconnaissance scans proved that single-probe flows do not produce enough statistical features for reliable classification.

We made the deliberate decision to decouple detection into two complementary engines: a stateful sliding-window tracker for rapid multi-port sweeps, and a Random Forest classifier for multi-packet conversational flows. This eliminated false negatives on stealth scans without adding algorithmic complexity.

DECISION 02

Metadata-Only Analysis Without Payload Snooping

Payload inspection introduces massive CPU overhead, breaks under modern TLS encryption, and raises critical end-user privacy concerns.

AI-NIDS restricts all feature derivation to Layer 3 and 4 headers: packet arrival intervals, byte volumes, directional ratios, and TCP control flag counts. Zero application layer bytes are retained or analyzed, ensuring total user data privacy.

DECISION 03

Compact 14-Feature Input Vector

The full CICIDS2017 dataset includes 79 network flow features, many of which exhibit high collinearity (e.g. forward inter-arrival time standard deviations) and require significant memory to compute in live streaming loops.

We selected 14 essential statistical indicators that provide maximum discriminatory power while maintaining minimal computational overhead. This allows the feature extraction function to execute in microseconds upon flow expiration.

CHALLENGES

Implementation Hurdles

Technical obstacles encountered and resolved during pipeline development.

Flow Expiration Synchronization

Determining when an inactive network conversation has officially terminated without maintaining stale sockets indefinitely in memory. Resolved via a 5.0-second inactivity check loop and immediate expiration upon seeing TCP FIN/RST flags.

Dataset Format Alignment

Aligning Scapy's real-time packet counters with historical CICIDS2017 feature definitions. For example, flow duration in CICIDS is measured strictly in microseconds (μs), requiring nanosecond-level clock normalization in Python.

LIMITATIONS

Known System Limitations

Current architectural boundaries established by hardware and language constraints.

Throughput Ceiling (User Space)

Because packet sniffing executes in Python user space via Scapy, kernel-to-user-space memory copies and Python's Global Interpreter Lock (GIL) cap sustained packet throughput to approximately 100 Mbps.

Multi-Flow Flood Correlation

The Random Forest model evaluates flows independently. Highly distributed DDoS attacks that send only 1 or 2 packets from thousands of distinct source IPs will not trigger single-flow statistical anomalies without an aggregated global rate analyzer.

DEVELOPMENT ROADMAP

Future Engineering Improvements

Planned technical advancements to transition AI-NIDS from an applied research prototype into a high-throughput edge security engine.

PHASE 01

eBPF / AF_XDP Kernel Packet Filtering

Replace Scapy's user-space listener thread with an in-kernel eBPF (Extended Berkeley Packet Filter) probe or AF_XDP socket. This will bypass user-space context switches and elevate packet ingestion throughput to multi-gigabit line rates.

PHASE 02

Semi-Supervised Online Model Adaptation

Implement streaming clustering (such as incremental MiniBatch K-Means or Isolation Forests) alongside the static Random Forest model to adapt dynamically to evolving network baselines and discover novel zero-day anomalies.

PHASE 03

Automated Active Response (iptables / nftables)

Integrate an active mitigation module capable of automatically synthesizing temporary Linux firewall rules (via nftables or iptables) to null-route confirmed malicious IPs when DEFCON threat scores breach critical thresholds.
