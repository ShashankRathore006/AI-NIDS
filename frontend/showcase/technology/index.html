Built With Practical Engineering Tools

AI-NIDS is deliberately implemented using proven, lightweight, and auditable open-source components. Every library and datastore choice was selected to maximize edge hardware efficiency, low-latency execution, and complete deployment independence without bloated container runtimes.

CORE COMPONENTS

The Operational Stack

We present the verified technology stack used in the production AI-NIDS codebase. Each tool was chosen for verifiable technical merits rather than industry hype.

01 / LANGUAGE

Python

Serves as the unified runtime connecting socket frame sniffing, mathematical matrix extraction, and web service delivery. Provides direct C-extension bindings for low-level packet libraries and machine learning runtimes.

Python 3.10+ threading collections.defaultdict
02 / NETWORKING

Scapy

Provides low-level promiscuous socket sniffing and deep packet protocol dissection across Ethernet, IPv4, TCP, and UDP headers. Enables rapid prototyping of packet filters and bidirectional flow assembly directly in Python user space without external compilation dependencies.

scapy.all.sniff AF_PACKET Interface Raw Socket Dissection
03 / INFERENCE

scikit-learn (Random Forest)

Implements an ensemble of 100 decision trees trained on 65,000 balanced benchmark samples to classify flow feature vectors. Executes sub-10ms CPU inference with zero GPU hardware requirements, making it ideal for deployment on edge gateways and micro-servers.

RandomForestClassifier 100 Estimators joblib Serialization CPU-Native Execution
04 / DATA PROCESSING

NumPy & Pandas

Formats real-time extracted flow statistics into strictly ordered 14-dimensional DataFrame rows matching model training schemas. Powers high-speed vectorized operations during training data preparation and batch evaluation.

pandas.DataFrame Vectorized Calculations Schema Integrity
05 / API SERVICE

FastAPI & Uvicorn

High-performance asynchronous ASGI application serving non-blocking REST endpoints for real-time alert dispatch and threat metrics. Features native CORS support and automatic OpenAPI Swagger documentation for seamless SIEM integration.

FastAPI ASGI Uvicorn Worker Port 8000 CORS Middleware
06 / PERSISTENCE

SQLite

In-process relational datastore logging 12 structured fields per flow alert with zero external daemon configuration or port overhead. Ensures atomic writes and instant forensic inspection via a single embedded file (database/nids.db).

sqlite3 C-Binding nids.db File Zero Daemon Setup
07 / PRESENTATION

Vanilla JavaScript (ES6+), HTML5, CSS3 & Chart.js

Lightweight, standards-based web client running with zero Node.js daemon and zero npm build steps. Utilizes pure browser DOM APIs, Web Audio synthesizer chirps, and Chart.js for real-time telemetry streaming and DEFCON risk evaluation.

Zero-Build Static Serving Chart.js UMD Web Audio API Python http.server
ENGINEERING TRADE-OFFS

Architectural Decisions & Justifications

Every technical choice balances operational simplicity against raw performance. Below are the engineering trade-offs evaluated during system design.

Decision Area Selected Technology Evaluated Alternative Engineering Justification & Trade-off Analysis
Packet Ingestion Scapy (User Space) libpcap / DPDK / eBPF Selected for: Rapid protocol dissection and pure Python portability without kernel compilation.
Trade-off: Lower throughput ceiling (~100 Mbps) compared to kernel-bypass DPDK, which is acceptable for edge IoT gateway demonstration.
Classifier Model Random Forest (100 Trees) Deep Learning (LSTM / Transformers) Selected for: Microsecond CPU inference, high tabular data accuracy, and transparent decision boundaries without GPU dependencies.
Trade-off: Incapable of temporal sequence learning across multiple disconnected flows without explicit feature state tracking.
Reconnaissance Detection Stateful Sliding Window Standalone ML Model Selected for: Immediate zero-delay alerts on multi-port sweeps where individual flows lack anomalous statistical distributions.
Trade-off: Requires in-memory state tracking per active IP address.
Database Engine SQLite (Embedded File) PostgreSQL / TimescaleDB Selected for: Zero administration, self-contained single-file storage, and zero background daemon RAM footprint.
Trade-off: File-level write locks limit high-concurrency ingestion at massive multi-gigabit scales.
Frontend Architecture Vanilla JS & Static HTTP React / Next.js / Angular Selected for: Instant load times, zero compilation build steps, zero node_modules vulnerabilities, and 100% portable Python hosting.
Trade-off: Imperative DOM manipulation requires manual state synchronization.
